# 日々のしおり — My News

iPhoneで読みやすい、日本語のニュースリンク集です。Macへのインストール、ターミナル、有料API、APIキーは不要です。作業と設定はCodexクラウドとGitHubのブラウザ画面だけで行えます。

## 今の状態

コードとActionsを用意した段階です。**サイトの公開は無効**になっています。PR作成やマージだけでは公開しません。`PAGES_ENABLED` が文字列 `true` の場合だけ公開ジョブが動きます。リポジトリ自体の公開・非公開設定は変更していません。

初期 `docs/data/news.json` は空です。架空ニュースは含みません。実際の収集に成功した後にニュースが表示されます。テスト用の記事は `tests/` の中だけにあり、サイトの公開対象には入りません。

## できること

- AI、テクノロジー、ビジネス、経済、バズ、グルメ、イベント、東京、沖縄、ハンドメイドの複数選択。
- 選択テーマの**いずれか**に該当する記事を表示（OR条件）。選択なしは全件。「すべて表示」で解除。
- 選択内容をこのブラウザのlocalStorageに保存。保存できない環境でも絞り込みは可能です。別端末・別ブラウザとは同期されず、ブラウザデータ削除で消えます。
- RSS掲載日時の新しい順、元記事URLによる重複除外、複数テーマの統合。
- 見出し、配信元（元記事のドメイン）、日時、元記事リンク、最終更新日時。
- 読み込み失敗、記事なし、収集失敗、48時間以上の更新遅延の案内。
- iPhoneホーム画面用のmanifest、PNGアイコン、Apple用メタ設定。

通知機能・通知ボタンはありません。Service Workerやオフライン配信もありません。ホーム画面から開く場合も通信が必要です。

## 情報取得元と利用条件の確認

確認日：2026年11月16日（日本時間）。公式の次の案内を確認してRSSを選びました。

- [はてな利用規約](https://policies.hatena.ne.jp/rule)：権利侵害・過負荷などの禁止事項と各ヘルプを確認。
- [過剰アクセスに関する注意事項](https://b.hatena.ne.jp/help/entry/notice_access)：HTML巡回ではなくRSS/APIの使用を案内。特定フィードへの取得は多くても30分ごと程度とされているため、通常は1日1回、手動の連続実行も保存済みの試行時刻で30分以内の再取得を抑えます。
- [公式開発ブログ：タグ検索RSS](https://bookmark.hatenastaff.com/entry/2019/09/12/191844)：`/search/tag?q=...&mode=rss` の形式を確認。

### 使うフィード

取得元はすべて **はてなブックマーク** です。各テーマについて `https://b.hatena.ne.jp/search/tag?q=テーマ名&mode=rss&sort=recent` を取得します（URLエンコードはスクリプトで処理）。「バズ」だけは総合人気エントリー `https://b.hatena.ne.jp/hotentry.rss` を使います。一覧とURLは `scripts/collect_news.py` の `FEEDS` にあります。

本文、要約、画像、ユーザーコメント、ブックマーク数は保存・表示しません。RSSに含まれる見出しと元記事URL、日時のみを取り出し、配信元ドメインとテーマを付けます。元記事のページは取得しません。元サイトとは別に情報取得元としてはてなブックマークをサイト内に表示します。

これは公式のRSS取得案内に従ったリンク集であり、各記事の転載許諾を取得したものではありません。記事の権利は各権利者に帰属します。利用条件が変わった場合は対象フィードを停止・変更してください。営利利用や本文等の再利用を加える際は別途条件の確認が必要です。

**表示の限界：** はてなブックマークのタグ検索にはブログや過去の記事も含まれ、各テーマを網羅するものではありません。分類はタグ検索由来で誤分類があり得ます。RSSの日時（`dc:date` / `pubDate`等）は元記事公開日時とは限らないため、画面では「RSS掲載日時」と表示します。公開日を推測したり、取得時刻を記事日時として補ったりしません。日時のない・不正な記事は除外します。

## 収集と障害時の動作

`.github/workflows/collect-news.yml` の **Collect news** が毎日 `22:00 UTC`（日本時間の翌朝7:00）を目安に実行されます。**GitHub Actionsの定期実行は遅延・未実行になる場合があり、7時ちょうどを保証しません。** スケジュールはデフォルトブランチのワークフローのみが対象です。公開リポジトリでは長期間活動がないとスケジュールが停止される場合もあります。

ブラウザから **Actions → Collect news → Run workflow → main → Run workflow** で手動実行できます（ワークフローがmainへ入った後）。1フィードあたり25秒のタイムアウト、最大2MB、最大80記事、全体で最新600件まで。追加のライブラリは不要です。

- `docs/data/news.json`：公開用ニュース。`updatedAt` は少なくとも1フィードを取得できた時刻（日本時間で画面表示）。一部が失敗してもこの時刻は更新されます。
- `docs/data/status.json`：最終試行日時とテーマごとの成功・失敗・キャッシュ利用、最終成功日時。
- `collector-cache.json`：テーマ単位の前回取得データと試行日時。初回実行で生成しGitに保存。公開成果物 `docs/` の外に置きます。

一部失敗なら、そのテーマの前回データと取得できたテーマの新しいデータを統合。**全件失敗ならnews.jsonはバイト単位で保持**し、statusとキャッシュの試行時刻だけ更新します。正常な空フィードは取得成功として扱います。ニュースを取得できなかった場合、Actions自体はstatus保存まで正常終了することがあるので、収集状態はサイトの案内・status・実行ログで確認してください。更新が2日以上止まった場合もサイトに案内します。

URLのフラグメント、`utm_*`、`fbclid`、`gclid` を除去して同一URLを統合し、他のクエリパラメーターは保持します。異なるURLで配信された同内容記事やHTTP/HTTPSの別URLまで同一とは判定しません。

## 後で公開するときのブラウザ操作

**今回は実行しないでください。** PRの確認・マージ後、公開を決めたときの手順です。

1. リポジトリ **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にします。
2. **Settings → Secrets and variables → Actions → Variables → New repository variable** で `PAGES_ENABLED` を作り、値を `true` にします。これは秘密情報ではなく、APIキーも不要です。
3. **Actions → Collect news → Run workflow** をmainで実行します。収集・コミットの後、同じワークフローからPages公開を呼び出します。
4. 完了後 `https://hy-app-web.github.io/my-news-app/` を開きます。

以降、日次収集後と `docs/` 等を変更してmainにpushした後に公開されます。`GITHUB_TOKEN`による収集コミットは別のpushワークフローを起動しないため、収集ワークフローから公開ワークフローを直接呼びます。画面だけ公開し直す場合は **Publish Pages → Run workflow** も使えます。

収集コミットが拒否される場合はActionsログを確認してください。mainへの直接pushを禁止するブランチ保護や組織ポリシーでは、収集データ保存方式の調整が必要です。通常はワークフローに必要最小限の `contents: write` を宣言しているため、個人トークンは不要です。公開には `pages: write` / `id-token: write` を公開ジョブにだけ付与しています。

公開を止める場合、変数を `false` にすると今後のデプロイが止まります。すでに公開済みのサイトを削除する場合は **Settings → Pages → Unpublish site** を使用します（変数だけでは既存サイトは消えません）。
